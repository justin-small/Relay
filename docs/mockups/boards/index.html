Boards

Admin › Live › Boards. Each board has its own address for a TV or tablet. Anyone signed in to Relay can open a board; a board marked Public opens for anyone on the viewer network. Editing needs boards.manage (Admin).

A board, live, and its editor

The board as a TV shows it. Press Edit (admins only): the palette slides in and the grid appears, while captions, the clock and the stream keep updating underneath. Drag a widget to move it, drag an edge or corner to resize, double-click (or Enter) for its settings. Save returns to the board.

Decided: grid with snap. A board picks its columns and rows (default 12 × 8) and its shape (16:9, 4:3, 9:16 portrait); every widget is a whole number of cells, so it lays out the same on any screen size.

Lighting cue page, on the same editor

Admin › Lighting › Cue pages. The page's form and preview are replaced by the shared editor. The palette is the cues the lighting program lists (or "Add by id" for Vista and Lightkey); each button gets the shared look: text, shape, colour, text colour, pressed colour, icon. The tablet on the right is /screen?lighting=…, drawn by the same renderer: tap a button to see it press.

Tablet: /screen?lighting=worship&key=… · the outlined button is lit in QLC+.

Decided: lighting pages saved with "Place buttons freely" (percent x/y/w/h) are moved onto the grid once, to the nearest cells, and the free option goes away. One layout model for every user of the editor.

Widget settings

One dialog for every item. Look is the shared style schema core validates for every user of the editor; Widget is the settings the item's owner (core for boards, the lighting module for cues) supplies and checks. Open it from any item in the editor; here are three to try.

How the pieces fit

Core owns the editor, the renderer and the style rules. A module never gets imported by core: it hands core a list of widgets through a Module method, the same way it feeds the network map.

Core · app/layout.py

  • clean_style(): label ≤ 60 chars, shape one of 4, colours #rrggbb, icon from a fixed set. Never raw CSS.
  • clean_grid(): cols 1–24, rows 1–24, items inside the grid and not overlapping.
  • Used by boards and by the lighting module for its cue pages.

Core · app/static/layout-editor.js + layout-render.js

  • RelayLayout.edit(root, {grid, items, palette, settings, onSave})
  • RelayLayout.render(item, kind): one drawing for the editor, boards and /screen.
  • Pointer and touch drag, edge and corner resize, keyboard, undo/redo.

Core · app/boards.py + /board/<slug>

  • Board store, create / duplicate / delete / export / import, boards.view / boards.manage.
  • Core widgets: captions per language, now/next, countdown, alerts, status, clock, text, board link.
  • Feeds come from existing streams (/stream, alerts, status).

Modules · Module.board_widgets()

  • Lighting: cue button (pressable). OBS: stream status, program scene. ProPresenter: current slide. Planning Center: service order.
  • Each widget: id, name, category, default size, settings fields, and a data feed it publishes.
  • Module off → its widgets leave the palette, and on a board they show "Lighting is off".
