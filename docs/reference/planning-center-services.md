# Planning Center Services API reference

Schedule your teams, manage your music, and revolutionize the way you plan your worship services.

Generated on 2026-11-11 from Planning Center's published API documentation (`https://api.planningcenteronline.com/services/v2/documentation`), version `2018-11-01`. 65 resources. Shared rules (authentication, rate limits, versions, paging) are in [planning-center-api.md](planning-center-api.md).

- **Base URL:** `https://api.planningcenteronline.com/services/v2`
- **Starting point:** [Organization](#organization) at `/services/v2`
- **Version header:** `X-PCO-API-Version: 2018-11-01`

**Action `assign_tags`**: `POST /services/v2/songs/{song_id}/arrangements/{arrangement_id}/assign_tags`

All tags will be replaced so the full data set must be sent.

It expects a body that looks like:

```json
{
	"data": {
		"type": "TagAssignment",
		"attributes": {},
		"relationships": {
			"tags": {
				"data": [
					{
						"type": "Tag",
						"id": "5"
					}
				]
			}
		}
	}
}
```

On success you will get back a `204 No Content`.

**Action `import`**: `POST /services/v2/service_types/{service_type_id}/plans/{plan_id}/import`

This action copies the team members, needed positions, items, and notes from a
source Plan or PlanTemplate into this (already existing) Plan.

Accepted attributes:
- `source_id` (Integer) ID of the PlanTemplate or Plan to copy from.

- `additional_target_ids` (Array[Integer]) IDs of other Plans to apply the source to. These are imported asynchronously. (default nil)

- `copy_items` (Boolean) Copy Items from the source. Requires editor permissions. (default false)

- `copy_people` (Boolean) Copy team members and needed positions from the source. (default false)

- `copy_notes` (Boolean) Copy Notes from the source. Requires editor permissions. (default false)

- `team_ids` (Array[Integer]) IDs of teams to copy people from when `copy_people` is set to true. If nil, `copy_people` copies from all teams. (default nil)

Permissions: requires scheduler on the target plan's service type (and on every
`additional_target_ids` plan's service type). Using a Plan as the source requires
viewer on its service type; using a PlanTemplate as the source requires scheduler
on its service type. Schedulers may only copy people for teams they lead;
`copy_items` and `copy_notes` require editor permissions.

Returns a `PlanImportMetadata` resource describing the outcome (e.g. whether any
copied people were missing required background checks).

- `order` (prefix with `-` to reverse): `created_at`, `item_count`, `name`, `note_count`, `team_count`, `updated_at`
- `per_page` (1 to 100, default 25) and `offset`

**Action `import`**: `POST /services/v2/service_types/{service_type_id}/plan_templates/{plan_template_id}/import`

This action copies the team members, needed positions, items, and notes from a
source Plan or PlanTemplate into this (already existing) PlanTemplate.

Accepted attributes:
- `source_id` (Integer) ID of the PlanTemplate or Plan to copy from.

- `copy_items` (Boolean) Copy Items from the source. Requires editor permissions. (default false)

- `copy_people` (Boolean) Copy team members and needed positions from the source. (default false)

- `copy_notes` (Boolean) Copy Notes from the source. Requires editor permissions. (default false)

- `team_ids` (Array[Integer]) IDs of teams to copy people from when `copy_people` is set to true. If nil, `copy_people` copies from all teams. (default nil)

Permissions: requires scheduler on the target template's service type. Schedulers
may only copy people for teams they lead; `copy_items` and `copy_notes` require
editor permissions.

Returns a `PlanImportMetadata` resource describing the outcome (e.g. whether any
copied people were missing required background checks).

**Action `item_reorder`**: `POST /services/v2/service_types/{service_type_id}/plan_templates/{plan_template_id}/item_reorder`

This can be used to reorder all items in a plan template in one request.

It expects a `POST` body with a `sequence` of `Item` ids in order.  E.G.

```json
{
  "data": {
    "type": "PlanItemReorder",
    "attributes": {
      "sequence": [
        "5",
        "1",
        "3"
      ]
    }
  }
}
```

On success you will get back a `204 No Content`.

### Proposing a replacement

When every time is declined the request falls through to the decline flow, and the optional `replacement_id` and `replacement_confirmed` attributes may be included. When the team is configured to reschedule declines with a volunteer replacement and `replacement_id` is present, the decline initiates the replacement workflow (contacting the chosen person). `replacement_confirmed` indicates whether the replacement has already agreed to fill in — skipping the confirmation step when true.

`replacement_id` is the `account_center_id` of the proposed replacement.

```json
{
  "data": {
    "type": "ScheduleAccept",
    "attributes": {
      "reason": "Because reasons",
      "replacement_id": "123",
      "replacement_confirmed": true
    },
    "relationships": {
      "declined_plan_times": {
        "data": [
          {
            "type": "PlanTime",
            "id": "1"
          }
        ]
      }
    }
  }
}
```

Note: `replacement_id` is not validated against a list of eligible replacements; any person in the organization may be submitted. The calling UI is responsible for presenting an appropriate list, matching the existing volunteer-chooses-their-own-replacement flow.

**Action `decline`**: `POST /services/v2/people/{person_id}/schedules/{schedule_id}/decline`

If this is a split time request, all times will be declined.

If you want to decline specific times see ScheduleAcceptAction.

A POST body should be formated...

```json
{
  "data": {
    "type": "ScheduleDecline",
    "attributes": {
      "reason": "A user supplied reason for declining the request or an empty string."
    },
    "relationships": null
  }
}
```
