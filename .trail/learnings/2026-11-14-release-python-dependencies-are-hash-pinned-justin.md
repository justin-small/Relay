## Decided
Issue 187 replaced Trivy-on-the-image. The desktop release installs requirements-release.txt with pip --require-hashes --only-binary=:all:. It is generated by `uv pip compile requirements-release.in --generate-hashes --universal --python-version 3.15`, so one file carries every platform's wheels and the platform markers (uvloop off Windows, cryptography 48.0.1 on Intel Macs) and PyInstaller with its own dependencies. tests/test_release_lock.py fails when a pin in requirements.txt is missing from it or lost its marker. The Tests workflow's "Dependency audit" job runs pip-audit on both files, npm audit on desktop/ and cargo audit on desktop/src-tauri on every PR.

## Tried and ruled out
Leaving requirements.txt as the release input with hashes added to it: pip --require-hashes then needs a hash for every transitive package too, and the test install (plus httpx2) would have to carry them.

## Watch out
- The first pip-audit run found certifi 2024.12.14 (PYSEC-2026-4320); it is now 2026.10.18. A new advisory against a pin fails every PR until it is bumped.
- cargo audit passes with five warnings (unmaintained zbus_names, zvariant, zvariant_derive; unsound glib 0.18) in Tauri's Linux dependencies; warnings do not fail it, a vulnerability would.
- Before a Python bump, every pin still needs a cp3XX wheel on every release platform (orjson's Linux wheels need glibc 2.39, so Ubuntu 24.04 runners).

In the code: requirements-release.in (the regenerate command), .github/workflows/tests.yml (audit job), .github/workflows/release.yml (Freeze the backend).
