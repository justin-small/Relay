## Decided
The Markdown reference for ProPresenter's HTTP API was generated by a one-off script from the OpenAPI description behind https://openapi.propresenter.com/, not written by hand. Only the Markdown was committed. The description file was left out because the repo is public and the file is Renewed Vision's, verbatim; the reference points at the published page instead. Justin was told and can ask for it to be added.

The generator was a throwaway script and is not in the repo. To refresh the reference, regenerate from the published description rather than editing 10,000 lines by hand.

## Tried and ruled out
- Reading the Swagger page itself: it is an empty shell that loads the description from a script file.
- Resolving cross-references as plain JSON pointers: about 50 failed until each pointer segment was percent-decoded first.

## Watch out
- The published file is JavaScript (`var openapi_spec = {...}`), not JSON: strip to the outer braces before parsing.
- It has no shared components section; every cross-reference points into another path, with `{` and `}` percent-encoded and `/` written as `~1`.
- One response (404 on GET /v1/look/{id}) points at a file that is not published; the reference marks it "not described".
- One parameter (`sse`) has a malformed type, and one operation spells its ID key `operationID`.
- The description names the path /v1/presentation/active but uses `presentation/current` as the name inside POST /v1/status/updates. Unconfirmed which a real install accepts.
- The description's default port is 50001; community notes said 50000.
